# StayUp

ふたを閉じたまま Mac を動かし続けるための常駐アプリと CLI。

- **ふたを閉じてもスリープしない**：root ヘルパーが `pmset disablesleep` を切り替える
- **必要な間だけ抑止する**：要求を、期限と要求元を持つ**リース**として扱う。尽きれば元に戻す
- **複数の要求を同時に扱う**：ビルドとエンコードが並行していても、片方が終わっただけでは解除しない
- **解除し忘れが起きない**：クラッシュしても `kill -9` されても、リースは消える
- **CLI から操作できる**：`stay-up run --owner build -- make release` でコマンドの実行中だけ起こしておく
- **安全側に倒れる**：バッテリー残量、発熱、総継続時間の条件は、どのリースよりも優先する

## インストール

```sh
brew install --cask tosaka07/tap/stay-up
```

Homebrew を使わない場合は、[Releases](https://github.com/tosaka07/stay-up/releases) から ZIP を取得し、展開した `StayUp.app` を `/Applications` に置く。
このときは CLI へのパスを自分で通す。

```sh
ln -s /Applications/StayUp.app/Contents/MacOS/stay-up ~/.local/bin/stay-up
```

macOS 26 以降で動く。
Apple Silicon と Intel の両方を含むユニバーサルバイナリで配布している。

### ヘルパーの登録

初回起動では、ふたを閉じたときのスリープはまだ抑止されない。
この操作だけは root 権限が要るため、専用のヘルパーを登録する必要がある。
アプリの診断タブから「ヘルパーを登録」を選び、macOS の「ログイン項目と機能拡張」で承認する。

承認が済むまでは、アイドルスリープの抑止だけが働く。
その状態でもアプリは使えるが、ふたを閉じるとスリープする。

### アンインストール

**アプリを削除する前に**、診断タブから「登録を解除」を選ぶ。
スリープ設定を元に戻してから root ヘルパーの登録を解除する。

先にアプリを消すと、ヘルパーの登録だけが残る。
`brew uninstall --cask stay-up` も同じで、削除の前に解除しておく。

## 使い方

### コマンドの実行中だけ起こしておく

```sh
stay-up run --owner build -- make release
```

`--` の後ろがそのまま実行され、終了コードも透過する。
リースはこのプロセスに紐づくので、`make` が終われば自動で消える。
クラッシュしても `kill -9` されても同じである。

抑止したい範囲がコマンドの実行時間と一致するなら、この形がいちばん確実である。
解放を書き忘れる余地がない。

### スクリプトの中で使う

コマンドを包めない場合は、シェル自身のプロセス ID に紐づける。

```sh
stay-up acquire --owner my-pipeline --bind-pid $$ --ttl 2h || true
```

`set -e` で途中終了しても、`kill` されても、シェルが消えればリースも消える。
`trap` による後始末は要らない。

### 定期的に延長する

開始と終了のイベントは取れるが、プロセスに紐づけられない場合は、期限を延ばし続ける形にする。

```sh
# 開始する。同じリースファイルがあれば何もしない
stay-up acquire --owner my-tool --if-not-exists --ttl 30m \
  --lease-file ./.stay-up-lease --label "long task"

# 進捗のたびに期限を延ばす
stay-up renew --lease-file ./.stay-up-lease --ttl 30m

# 終了する
stay-up release --lease-file ./.stay-up-lease
```

最後の `release` が実行されなくても安全である。
延長が止まれば期限切れで自然に消えるので、`release` は早く解放するための最適化でしかない。

### メニューバーから操作する

メニューバーのアイコンから「StayUpを開始」を選び、30分、1時間、2時間、無期限のいずれかで始める。
実行中のセッションは同じメニューに並び、残り時間と要求元を確認できる。
「すべて解除」ですべてのリースを解放する。

キーボードからも操作できる。
`⌃⌥⌘1` から `⌃⌥⌘4` が上と同じ順で開始し、`⌃⌥⌘0` がすべて解除する。

### 状態を見る

```sh
stay-up status          # 人が読む形式
stay-up status --json   # tmux やプロンプトに埋め込む形式
stay-up list            # 有効なリースの一覧
stay-up doctor          # ヘルパーと権限と pmset を診断する
```

引数なしで `stay-up` を実行すると、抑止の開始と解除を切り替える。
`start` と `stop` も同じ意味で受け付ける。

## 仕組み

### なぜ caffeinate では足りないのか

macOS 標準の `caffeinate` が止められるのはアイドルスリープだけで、ふたを閉じるとスリープする。
ふたを閉じても止めないには `pmset -a disablesleep 1` が要る。

この設定はシステム全体で一つしかなく、設定したプロセスが死んでも 1 のまま残る。
戻し忘れた Mac は、誰にも管理されないまま鞄の中で発熱し続ける。
StayUp が抑止に期限と紐付けを持たせているのは、この状態を作らないためである。

### 抑止を要求する主体は一つとは限らない

単純なオンとオフで扱うと、片方の作業が終わっただけで全体が解除される。
ビルドとエンコードを同時に走らせていて、ビルドが先に終わったら、エンコードの途中でスリープしてしまう。

StayUp は要求を個別に追跡し、有効なリースが一つ以上あるあいだだけ抑止する。
所有者は自分のリースだけを解放でき、他人の要求を壊せない。

### 元に戻すことを何重にも保証する

`pmset disablesleep` はシステム全体の設定なので、放置されると誰にも管理されない状態になる。
StayUp はこれを避けるために、復元の経路を重ねている。

| 経路                            | 何をカバーするか              |
| ------------------------------- | ----------------------------- |
| 正常な解放                      | 通常の操作                    |
| root ヘルパーによる接続断の検知 | アプリのクラッシュ、`SIGKILL` |
| 終了通知を受けての明示的な解放  | ログアウト、再起動            |
| ヘルパー起動時の孤児チェック    | 電源断、カーネルパニック      |
| ハートビートの途絶を見る監視    | 接続だけが生き残る異常        |

中心にあるのは二つ目である。
root ヘルパーはアプリとの接続が切れたことを検知でき、切れれば理由を問わず設定を戻す。
アプリを強制終了しても、この経路が働く。

### 外部から操作されることへの備え

CLI から抑止を要求できるということは、「Mac をスリープさせない権限」を外部に渡すということである。

外部クライアントのリースには必ず期限が付く。
無期限が許されるのは、画面から人が操作した場合だけである。
バッテリー残量、発熱、抑止の総継続時間という条件は、どのリースよりも強い。
これらに達すると、すべてのリースが失効する。

`--owner` は自己申告の文字列であって、認証ではない。
意図しない抑止に気付いて取り消せるようにするための識別であり、悪意ある動作を防ぐ仕組みではない。

設計の詳細は [`docs/spec.md`](docs/spec.md) にある。

## 制限

いずれも 0.1.0 時点のものである。

**他のスリープ抑止ツールとの併用は想定していない。**
`pmset disablesleep` はシステム全体で一つの値しか持たないため、どちらかの解除がもう一方を巻き添えにする。
StayUp のヘルパーは起動時に、所有者のいない `disablesleep=1` を戻す。
このとき他のツールが設定した値も戻してしまう。

**ヘルパーの表示が実態とずれることがある。**
アプリは macOS への登録記録を見て「有効」と表示するが、実際に通信できるかまでは確かめていない。
登録が残ったまま実体が失われた場合、有効と表示されたまま抑止が効かない。
`stay-up doctor` は実際の `pmset` の値を読むので、疑わしいときはこちらで確認できる。

**通信が切れたときの再接続を試みない。**
ヘルパーとの接続が切れると、アイドルスリープの抑止だけが残る状態へ即座に降格する。
降格したことは通知される。

**通知は二種類しかない。**
バッテリーや発熱による強制解除と、スリープ設定の復元失敗だけを通知する。

**CPU の使用率による自動解除は未実装である。**

**コントロールセンターには対応していない。**
理由は [spec](docs/spec.md#スコープ外とした導線-コントロールセンター) に書いた。
